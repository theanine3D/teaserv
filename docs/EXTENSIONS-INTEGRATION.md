# Extension integration map

Upstream source baseline: `46ab6f106618060157b8fc99e840bb6be4f15c11`. This file records the small set of hooks to review after an upstream merge. Do not infer runtime compatibility from a clean textual merge.

Use the [offline upstream audit](EXTENSIONS-UPSTREAM.md) before integrating a locally available upstream candidate. Its machine-readable [watch inventory](EXTENSIONS-UPSTREAM-WATCH.json) includes the hooks below and related services whose behavior can change without touching a hook. Update both maps when adding integration surfaces. The tool keeps the recorded baseline unchanged; advance it only after recording a successfully integrated upstream revision and its validation. A path report is not a substitute for inspecting changed callees or running compatibility checks.

Only `src/Extensions/Manager` knows about Newserv clients, account flags, configuration, lobby state, and native send helpers. `Runtime`, `SceneService`, and format inspection depend on C++/Lua only and remain independently testable. `NativeAssets` reuses upstream BMP/GVM/PRS code during staging. Scene traffic uses existing `send_ep3_media_update` and `send_change_event` helpers, with exact retail-Episode-3 gates around all extension-driven B9 sends, including resets.

Server-wide announcements add no upstream call site. Preserve `chat.announce` as a distinct administrator grant, native event-invocation authority (never inferred from Lua tables), and the additional `ANNOUNCE` account check for commands/player timers. Observation callbacks still lack player actions; only the separately granted announcement operation is available. Load callbacks can announce once native services exist; staging/migrations/unload cannot. Manager-owned monotonic package/global cooldowns must survive runtime replacement and must not be reset by checks or refused attempts. Fanout uses existing per-client `send_text_or_scrolling_message`, escaped/bounded extension text, and local authenticated/connected/version/BB-phase/proxy recipient gates; preserve recipient-failure isolation and the distinction between acceptance and client rendering. Review upstream send, session phase, and `GameServer::all_clients` changes even when this adapter merges cleanly.

`CommandArguments` is a bounded, pure C++ parser owned by the isolated extension runtime. Schema validation and generated usage need no additional upstream hooks. Preserve authorization-before-parsing, invalid-input-before-cooldown ordering, exact integer/session-ID handling, and the original raw second Lua argument when integrating command dispatch changes. The third handler argument is a parsed table only for schema commands; existing callbacks remain compatible.

Native media ownership is shared with upstream configuration. Preserve the baseline initialization hook, recipient cache, delete-all/replay ordering, and cleanup on reload/unload/fault. Baseline banner changes reconcile periodically; source comments' eight-group behavior still requires client confirmation. Canonical CARD layouts (blocks 16..20 with no lobby-number override) are supported conservatively; review upstream lobby-type selection if expanding this subset. An event override restores only when the current event still equals its last applied value, so intervening admin changes usually win.

The manager holds a weak server reference and its own shared I/O-context reference so timer destruction remains valid during server teardown. The executor owns runtime mutation; scripts cannot invoke shell actions, reload themselves, yield, or concurrently mutate manager state. Context identity is the connected session's server ID plus its original lobby ID. Actions revalidate those identities and current permissions; script context tables are only snapshots.

`LiveMembership.hh` records the synchronous eligibility contract used by `Manager::live_client`. Preserve current registry lookup, the client's matching server ID, exact registered Lobby pointer identity, matching lobby ID, and actual own-slot occupancy, plus local GAME_SERVER role, non-unknown/non-patch/non-pre-V1 version, BB phase, authentication, channel connection, and proxy exclusion. `is_pre_v1` excludes only DC NTE and November 2000, not every prototype/trial. Account/chat-command permissions belong in `authorized`, not recipient membership: safe error replies and less-privileged/muted recipients must not inherit the sender's permission requirement. Broadcast and lobby enumeration additionally compare the iteration slot to the client's stored slot and compare the resolved current client to the enumerated shared pointer. Whisper/reply reuse the same resolver. No new upstream hook is added. The source audit confirms GameServer registers clients before receiving commands, create_lobby registers lobbies before addition, and add/change membership completes before join callbacks. Leave-before-removal and move-before-leave retain their existing different action availability; existing cancellation hooks must remain intact.

`SessionLifecycle` retains only the last context snapshot for admitted local sessions and consumes it before disconnect callbacks. Admission gates exclude missing authentication, disconnected clients, non-game-server roles, patch/unknown versions, BB data phases, and proxies; replay managers are absent. Preserve proxy handoff forgetting, deduplication across repeated login procedures, and the disconnect-before-membership-leave ordering. Runtime forces both session events into a read-only player-action scope independently of Manager authorization. Context version/game metadata is descriptive and never a capability or modified-client identifier. Snapshot tracking survives package reload but is not a historical event replay or persistent account ledger.

Package `storage_version` and persisted `data_version` are independent of the format-1 storage envelope and package release string. Migration callbacks use staged runtime copies and restricted storage-only access; all candidate validation must precede activation and persistence of those copies. Keep startup corrupt-data refusal, downgrade rejection, equal-version skip, dirty-state retry, and per-package flush error isolation intact. No additional upstream hook is needed; `extension-storage-smoke` exercises real disk writes, rollback, restart, and recovery through the existing local shell.

Check and reload share `Manager::stage_config`: only activation mode flushes old storage or enters cleanup/swap/reconcile. Validation-only mode discards candidates after all catalog checks, including staged migrations. Keep candidate name-lookup scoping/reset and independent failure diagnostics intact when changing the loader. Runtime health/command metadata are read-only C++ snapshots; inspection never invokes Lua. Callback counters exclude initialization/migration/input rejection and peak allocation is recorded by the existing Lua allocator. No client packets or account permissions are changed by these administration features.

Callback timing is recorded in `Runtime::call` after protected Lua execution and native snapshot cleanup, before error reporting. The start derives from the existing deadline/budget constant; preserve accounting on success, errors, and OOM, plus exclusion of non-invoked timers and staged initialization/migration. Native calls and scheduler delays during an invocation contribute elapsed time. The last/peak/total/deadline metrics are copied into diagnostics and formatted only by Manager info; they never trigger a new failure, change hook budgets, or run Lua during inspection. Preserve fresh-runtime reset, rejected-staging isolation, and saturating totals. No new upstream hook, Lua authority, or packet is added.

`Runtime::schedule_timer` implements one-shot after and repeating every under the same grants/limits. `tick` selects one earliest-due timer (ID tie-break), removes one-shots before invoking, and retains repeating entries/slots through invocation. Never retain map iterators across Lua: callbacks may cancel themselves, create new timers reusing freed registry references, or fault/clear the package. Re-find the stable ID after return; only a still-owned successful authorized repeat is rearmed at completion plus interval. Failures remove the repeat without changing package fault policy. Preserve leave/disconnect cancellation and the original context's authorization checks; new repeating callbacks gain no startup/observer authority. No upstream hooks or packets change.

`extensions scenes ID` uses the existing feature-guarded shell dispatcher and `SceneService::diagnostics` value snapshots, filtered by the loaded package ID. Preserve bounded owner filtering and deterministic order, complete primary/fallback sizes and model build metadata, and separation from recipient planning/cache commits. Object/event records describe registry intent; inspection must not invoke Lua, refresh files, synchronize media, or imply actual delivery/rendering. No new lifecycle or network hook is required.

Optional scene lifetimes stay in `SceneService::Object` as monotonic deadlines and configured millisecond durations, not client/session handles or Lua timers. Runtime validates the optional argument before the adapter; native service validation also bounds it. Manager expires due objects before tick callbacks, spawning, and recipient planning, merges affected lobby nodes into the existing dirty set, and reconciles via existing media send gates. Preserve collection-before-erasure on allocation failure, successful-replacement-only deadline changes, no stale timer after key/slot reuse, and ordinary owner/catalog/pruning cleanup. Inspection reports the configured duration without refreshing expiry state. Background expiration proceeds independently of checks or player authority; it grants no new Lua callback/action scope and adds no upstream hook.

`scene_asset_support` shares `SceneService::select_variant` and `check_asset_support` with the actual native planner. Keep complete original-fallback selection, no implicit PC-to-original downgrade, profile compatibility, model switch, and exact selected-variant build allowlist in that shared helper. Manager supplies current authorized recipient state and an explicit disabled-backend result; Runtime supplies the immutable package ID and refuses live queries in observation scopes. Inspection never plans/sends packets or changes object/cache state. Preserve the planner's separate baseline/slot/quota decisions and final sender gates; support is not registration, delivery, or rendering proof. No new upstream hook or client protocol is added.

Command discovery stays inside `src/Extensions/`: the Manager copies command details only from enabled active runtimes after live-context authorization; Runtime requires `commands.read`, validates the bounded catalog, filters each permission against an immutable native context copy, and sorts before constructing Lua tables. Preserve current membership/phase/account checks through `authorized`/`live_client`, observation-scope refusal without adapter access, protected-call snapshot cleanup, and the 16-package/32-command limits when integrating upstream changes. Discovery never dispatches a command or relaxes its later permission/cooldown checks. The optional command-help package uses existing reply helpers; no new upstream hook or packet is added.

The baseline call-site audit found all external `Lobby::add_client`/`remove_client`/`move_client_to_lobby` calls routed through ServerState (plus Lobby's internal move implementation). Preserve that property during upstream integrations: a future direct call elsewhere would bypass these membership hooks. Do not use membership events as rendering-ready notifications. Timer cancellation also checks identity at execution time; additional scene/session generations should accompany future scene APIs.

For upstream integrations: fetch upstream; branch from `extensions`; merge the selected upstream commit; inspect these hooks and any changed callees; build/test both modes; run relevant real-client checks; record the new upstream revision and results. Keep mirror `master` free of extension commits. Local implementation does not create commits, pushes, or pull requests; the repository owner handles those manually.

The Windows follow-up reproduced shutdown and character-conversion failures with extensions disabled. Keep these portability fixes distinct from extension hooks when preparing local commits for review. `NEWSERV_TEST_DATA_DIR` changes only test working data; `PrepareTestFixture.py` builds a fresh fixture from tracked files and materializes link targets without rewriting the checkout or copying ignored player/account/configuration files. `ReplayLineEndingsTest.py` requires successful LF and CRLF replays and explicit completion markers.

Package settings are confined to `src/Extensions/Settings.hh/.cc`, the Manager JSON adapter, and the Lua runtime. The typed validator has no Newserv, JSON, or Lua dependency. Settings use the existing config snapshot and staged activation path; no additional upstream hooks or client packets are required. Preserve validation-before-activation, immutable active values, and value-free metadata when integrating upstream configuration changes.

Read-only lobby queries reuse the existing manager context and authorization services; no upstream call site is added. `LobbyView.hh/.cc` defines bounded, language-neutral snapshots. `Manager::lobby_view` reads only the caller's current lobby array and filters authentication, channel state, proxy state, membership pointers, and current server-session identity. The runtime checks scope/size/identity invariants and copies fields into Lua. Preserve the per-query permission check, current-session filtering, and the absence of account/private fields when upstream lobby or Client lifetime changes.

Package lifecycle uses only the extension manager and runtime; it adds no upstream hooks. Preserve the explicit activation boundary: staging/checking constructs runtimes without notifications; after the map/dependency/order swap, retire old instances in reverse order and activate new ones in configuration order. Old unload handlers cannot write storage copied during staging. Disable and graceful Manager destruction notify before discarding runtimes, but cleanup must not depend on callback success. Load callbacks have no player authority. Post-commit script faults and scene-reconciliation errors must not be presented as rejected staging or rollback.

Primary-game tracking is isolated in `GameLifecycle.hh/.cc`; metadata has no upstream or Lua dependencies. Existing Manager membership joins admit a game only after a successful local join, with current Client/Lobby registry identity, slot, authentication, connection, phase, and primary-game checks. Deduplication is independent of packages and occupancy, so persistent empty/refilled games and package reloads do not reopen. `Manager::game_closed` consumes admission once after ServerState registry removal and copies current bounded metadata. Callbacks have no player context and cannot act on the removed game. The source audit found the only explicit `id_to_lobby.erase` in `ServerState::remove_lobby`; review any new erasure/clear paths during upstream integration. Preserve upstream ordering rather than asserting one universal final leave/close order.

Quest observation state shares the isolated GameLifecycle tracker. Preserve one assignment and one matching map preparation per registered primary-game lifetime; zero is a valid quest number. Existing set_lobby_quest guards reject a second assignment, and the source audit found no other quest pointer assignment/reset. Revisit the tracker if upstream introduces quest replacement/restarts inside one game. Snapshot joinability comes from canonical Quest metadata. Do not synthesize map events from file acknowledgements, late-join synchronization, or disconnect/barrier releases that do not run on_quest_loaded; V1/V2 and later versions have different native paths. Manager registry identity, primary-game admission, and post-removal suppression remain mandatory.
